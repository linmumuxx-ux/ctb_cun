# 无界面多子系统逻辑题的测试设计方法

给子系统 subagent 和编排器使用。题面是接口和逻辑、模块之间有数据传递时，用这里的方法选故障假设和区分值。建设、组军、争夺、结算只是例子，不是某道固定题目。题面没有的环节写入 `gaps`，不编造规则。

这些方法不代替 `design-playbook.md`。假设仍要写成可达、激发、传播，算子仍用手册 §4 的名称。不写测试规格说明书或 testspec。`case_sketches.method` 填本节编号（如 `M1`）。

| 编号 | 方法 | 题面里出现这些就用 |
| --- | --- | --- |
| M1 | 资源 / 经济守恒与流向 | 产出、消耗、存量、货币、人口、次数 |
| M2 | 回合或时间推进与 tick | 回合、冷却、倒计时、周期结算、tick |
| M3 | 战斗判定与公式 | 伤害、攻防、克制、取整、随机 |
| M4 | 状态机与生命周期 | 建造、升级、队列、取消、完成、销毁 |
| M5 | 规则组合与判定表 | 多条加成、限制、折扣同时生效 |
| M6 | 多方竞争与并发 | 同一对象被多方同时操作，平局，归属 |
| M7 | 排名与结算 | 积分、名次、并列、重复发奖 |
| M8 | 属性与不变量随机序列 | 规则多、路径长，手写组合盖不住 |
| M9 | 蜕变测试 | 公式应满足缩放、交换、保序等关系 |
| M10 | 配置和数值表边界 | 系数、阈值、掉落或价格来自表 |
| M11 | 跨子系统数据流 | 上游输出是下游输入 |

## M1 资源 / 经济守恒与流向建模

**何时用。** 任何会改变存量的操作：生产、消耗、转化、取消返还、奖励入账。

**怎么推导。** 先画流向，不画界面：每种资源的来源、去向、存量。为每条成功操作写恒等式：`操作后存量 = 操作前存量 + 产出 − 消耗`（含手续费或损耗）。失败操作的恒等式是两边相等。再取区分值：存量为 0、比消耗少 1、刚好等于消耗、上限−1 次产出、刚好上限、再产出 1。同一资源做一次往返（产出后再按规则消耗回去），检查是否变多。

**打中的缺陷。** 失败仍扣资源；取消返还大于消耗，反复取消就能无限增加；产出与消耗用了不同的取整，来回一次变多；只改了展示用的副本，查询读到的存量没变；并发两次消耗只扣了一次或扣了两次。

例子：建设每 tick 产出粮食，组军按固定消耗扣粮食。往返或取消升级后粮食变多，就是刷资源。

## M2 回合或时间推进与 tick 结算

**何时用。** 规则依赖回合数、冷却、到期时刻，或每个 tick 结算一次产出、伤害、积分。

**怎么推导。** 列出每个 tick 要结算的写入，以及题面规定的顺序。用例至少覆盖：时间为 0（不结算）、推进 1 个单位、刚好到期、到期再加 1 个单位、一次推进跨过多个结算点。若同一 tick 内有多笔结算，按题面顺序各做一条「交换顺序就会得到另一个结果」的数据；题面没写顺序则记入 `gaps`，不假设谁先谁后。跨回合用例在回合边界两侧各读一次存量。

**打中的缺陷。** 到期时刻用了 `<` 而不是 `<=`，或多结算一次；一次推进跨过两个 tick 却只结算一次或结算两次；同一 tick 内先扣费再产出与先产出再扣费结果不同，实现顺序与题面相反；冷却在回合切换时被重置或没有重置。

## M3 战斗判定与公式验证

**何时用。** 胜负、伤害、战损、治疗由公式决定，公式含系数、取整、上下限或随机。

**怎么推导。** 把公式拆成题面写明的顺序：基础值、加减、乘系数、克制、上下限、取整。每个因子单独变化一条，其余固定，用来核对那个因子。再取会让取整改结果的值：结果刚好为整数、比整数少一个最小单位、比整数多一个不足 1 的小数。上下限取刚好等于下限、下限−1 的原始值、刚好上限、上限+1。攻防比较取相等、攻比防少 1、攻比防多 1。随机只在题面给出种子或可注入序列时设计：固定种子重复两次，结果相同；换一个种子，结果仍落在题面允许的集合内。没有种子就不要写「概率大约多少」的断言，只断言结果属于合法集合，并在 `gaps` 注明无法做分布检验。

**打中的缺陷。** 克制系数乘错边或用了加法；取整方向反了；下限没生效，伤害变成 0 或负数；上限没截断；攻等于防被算成一方胜利；随机没吃种子，两次相同输入结果不同，或种子改了结果却超出合法集合。

## M4 状态机与生命周期

**何时用。** 对象有明确状态，例如未开始、进行中、已完成、已取消，或队列中的等待、执行、完成。

**怎么推导。** 从题面列出状态、事件、守卫和伴随的资源写入。每个合法迁移一条；每个题面禁止的迁移一条；到达终态后再发一次同一事件。取消和回退各一条：取消后资源按题面返还，状态回到指定态，不能停在「取消中」。队列用例覆盖空队列、最后 1 个空位、超过容量。迁移之后立刻读状态并做下一步操作，确认没有停在题面未定义的中间态。

**打中的缺陷。** 非法迁移被接受；终态还能再升级或再领奖；取消后资源没返还或返还过多；回退后等级或队列占用没有回到迁移前；两个事件并发时停在题面没有的状态；队列超限仍插入。

例子：建造从空闲到建造中，再到完成或取消。取消后仍占着队列，或完成后还能再取消，都属于这一类。

## M5 规则组合与判定表

**何时用。** 两个以上条件或加成共同决定一个结果：多种限制叠加、多种百分比与固定值加成、折扣与上限一起生效。

**怎么推导。** 条件桩用能判定真假的句子，动作桩用可观察的数值或错误码。全部为真一条；每个条件单独为假各一条，且只让这一个条件为假。加成按题面顺序计算：先百分比后固定值，与先固定值后百分比，各用一组会分叉的数字（避免 0 和 1）。题面写了优先级就同时违反两条规则，断言先返回哪一个错误码；没写优先级则两条失败分开测，组合优先级记入 `gaps`。叠加上限单独一条：两项相加超过上限时结果等于上限。

**打中的缺陷。** AND 写成 OR，缺一个条件仍成功；百分比和固定值顺序反了；后一个加成覆盖了前一个而不是相加；超过上限没有截断；多个失败条件同时出现时返回了错误的那个码。

## M6 多方竞争与并发

**何时用。** 两个以上主体可以操作同一对象：同时占领、同时购买最后一件、同时领取同一奖励。

**怎么推导。** 先写单方成功和单方失败，再写并发。并发的预期只有题面允许的那一种：恰好一个胜者，或按明确的冲突规则分出结果。断言最终只有一个归属或一份库存，失败者的资源按题面退回或不扣。平局单独构造：双方关键数值相等，以及取整之后才相等。归属切换覆盖无主被占、易主、防守成功则归属不变。重复对已属于自己的对象再争夺一次，结果按题面是拒绝或无变化。

**打中的缺陷。** 双方都变成唯一归属者；库存被扣成负数或超卖；平局被当成某一方胜利；失败方也被扣了资源；后写入的一方覆盖了先结算的合法结果，且与题面顺序不符。

例子：两支军队同时争夺同一块无主领地，结束时只能有一个归属。

## M7 排名与结算

**何时用。** 把胜负、占领、资源或用时收成积分和名次，或给名次发奖。

**怎么推导。** 按公式逐项手算。每一项单独为 0、其余正常，用来核对系数；全部为 0；刚好达到上榜或分档阈值；差 1；分数上限与上限之上。并列至少两方同分，若有次级排序键再加一条「积分相同、次级键不同」。题面规定跳号还是连续名次，断言具体名次数字。零分和负分（仅当题面允许负分）各一条；题面不允许负分时，构造会导致负数的输入，预期被截断或拒绝。同一结算标识提交两次，以及并发提交两次，积分和名次只变化一次。

**打中的缺陷。** 漏乘某一项或取整时机错；0 分被排到错误名次；并列时不稳定，两次相同输入名次不同；下一名次该跳号却连续，或相反；重复结算再次加分；负分把名次或后续奖励算穿。

## M8 基于属性的测试和不变量随机序列

**何时用。** 命令很多、顺序会改变状态，手写组合仍然漏路径。适合作为 P1/P2，不代替上面各节的 P0 边界。

**怎么推导。** 先列出每一步之后都必须成立的不变量，例如存量非负、不超过上限、已结算标识不会再次增加积分、队列长度不超过容量、战损不超过出征数。用固定种子生成短序列（建议 4 到 8 步），每步之后断言全部不变量。序列里混入合法操作和一种非法操作。同一序列再跑一次，观察结果相同。不变量被打破时，把该固定种子的序列写成一条普通用例，不保留「随机所以不写步骤」的草稿。没有可用的随机源时，手写两条不同顺序的短序列即可，并在 `gaps` 注明未做长序列。

**打中的缺陷。** 只在特定顺序下出现的重复扣费、状态泄漏、负数存量；单条用例看不出来的上限被绕过。它不负责证明某一个公式系数，那是 M3 和 M5 的事。

## M9 蜕变测试

**何时用。** 正确结果难逐项手算，但两条执行之间的关系可以从题面推出来。例如线性缩放、交换参与方、与顺序无关的加法。

**怎么推导。** 写关系，不写单个魔法数字。线性公式：输入乘以 k（k 取 2 或 3，避开 0 和 1），输出按同一规则缩放；若有上下限，再补一条缩放后会触顶的关系。交换双方：若题面没有主场或先后手优势，交换后胜负对调、数值对调；若有优势，关系改成题面写明的不对称，不能默认对调。保序：只增加一方的某一项时，名次不会变差。两条执行都要从同一初态开始。

**打中的缺陷。** 系数写错但在 k=1 时看不出来；操作数写反；不该交换的字段被交换；排序不是稳定的，加分之后名次反而下降。

## M10 配置和数值表边界

**何时用。** 阈值、系数、价格、权重来自题面中的表或配置，而不是写死在一句规则里。

**怎么推导。** 表的使用方至少覆盖：空表、只有一行、缺一个必填字段、字段为 0、字段为题面允许的最大、最大+1、重复键、引用了不存在的键。每条只破坏表的一个方面，其余用合法最小表。预期是题面的错误码或明确的默认值，并且不把半行配置写入存量。权重或概率表还要断言权重和是否被当作合法（和为题面要求的值）；不符合时拒绝，不按未归一的权重继续抽。

**打中的缺陷。** 空表被当成 0 系数导致除零或全胜；缺字段时读到上一次的残留；极值溢出；重复键取了第一行或最后一行与题面不符；未知键被沉默地忽略并继续结算。

## M11 跨子系统数据流与端到端链路

**何时用。** 一个子系统的输出是另一个子系统的输入。编排器在合并之后用本节补联动；子任务只在 `propagate` 里写明自己要交出的字段。

**怎么推导。** 按题面箭头逐段做，再做一条整链。每一段至少三条：传递成功，下游读到的值等于上游写出的值；上游比下游门槛少 1，下游拒绝，两边存量保持；同一输出重复提交，下游只生效一次。整链用一组具体数字走完题面中的前后关系，例如产出的资源数量等于下游消耗前的持有量，下游形成的结果再进入再下游的计分。数字来自题面公式，不使用本节例子里的名称作为断言。

**打中的缺陷。** 上游写了 A 字段，下游读了 B 字段；单位或取整在边界上被做了两次；下游失败却让上游已经提交的产出消失或再次增加；整链上某一段的拒绝没有阻止后续结算，失败仍拿到了胜利奖励。

例子：建设产出的资源进入组军，组军得到的数量进入争夺，争夺的胜负进入结算。只测其中一段的内部公式，发现不了字段或单位在交界处出错。
