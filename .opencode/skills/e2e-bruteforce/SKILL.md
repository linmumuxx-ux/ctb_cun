# 场景暴力解

被测接口能在本地执行，并且能拿到正确版本的返回值时用。不负责取题和平台评测。

自己读题，自己看接口怎么调、正确版本怎么启动、返回长什么样。下面只规定顺序。

## 何时用

题目里有可执行的正确版本，调用接口就能看到它的真实返回。用这份返回当 oracle，期望值来自这一次运行，不来自对题目文字的推算。

e2e-test 按子系统设计用例，期望值由模型根据规则自己定。本技能不替换那条流程。

正确版本跑不起来就停下，说明缺什么。不要把有缺陷的被测版本返回写成金标准，也不要编造返回值。

## 流程

1. 按场景暴力铺开。把会让返回或状态不一样的情况尽量列出来，包括正常、边界、失败，以及会改变后续返回的先后顺序。
2. 写一个可执行脚本，对这些场景调用本地正确版本，打印每一次调用的返回。
3. 跑这个脚本，把打印出的正确返回原样记下来。这份记录就是 oracle。
4. 再写一个新脚本，对同样的场景、同样的调用顺序做断言。期望值只用第 3 步记下的结果。

两个脚本都放在题目目录里，并能在本地直接跑。路径按题目现有结构自定。

## 交给调用方

入参与 e2e-test 相同：`subject_root`、`profile`、`mode`、`round_target`、`work_order`。`profile` 和 `mode` 不改变上面四步。`work_order` 里点名的场景，仍按这四步做。

返回四件事：铺了哪些场景、oracle 记在哪、断言脚本在哪、正确版本是怎么在本地跑的。

## 和 loop

单独加载 `.opencode/skills/e2e-bruteforce/SKILL.md`。
