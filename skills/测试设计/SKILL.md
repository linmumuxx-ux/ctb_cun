# 测试设计

目标是在有限时间内交出一条评委能顺着读完的链：范围与风险 → 可测试需求 → 测试点 → 设计方法 → 用例 → 追溯与覆盖自检。

游戏题的厚度放在规则可判定、数值与取整、状态迁移、资源守恒、时间边界、并发幂等。外围文案和排列组合只保留测试点。

## 评分对齐

先找赛题里的评分表、评分标准、提交模板。找到了就以评分表的章节、权重和字段名为准，权重高的部分写到用例级。

仓库未附评分表时，默认按下表组织交付物，并在文首放「评分点对照」。这张表综合了测试设计赛常见的六段评分：需求分析、测试架构、详细设计、用例规范、工程一致性、文档。

| 评分关注 | 交付章节 | 写到什么程度 |
| --- | --- | --- |
| 测试需求分析 | 范围与风险、测试需求 | 每条需求可观察、可判定；歧义、假设、不测项分开 |
| 测试点 / 架构 | 测试点 | 模块 × 维度，主循环和资源、数值、存档更厚 |
| 详细设计 | 方法说明、用例 | 复杂逻辑标明方法；重点用例覆盖组合、临界、回滚 |
| 用例规范 | 用例表 | 字段齐全、步骤可执行、预期可判定、全卷不重复 |
| 工程一致性 | 追溯矩阵 | 需求 → 测试点 → 方法 → 用例不断链 |
| 文档 | 全文与自检 | 术语统一、优先级可见、文末有覆盖自检 |

职业技能赛若按「用例条数 + 重点用例覆盖复杂逻辑 + 用例规范」计分：先把复杂逻辑做成重点用例，再用边界补厚度。同一判定点只留一条用例。

## 工作顺序

1. 通读赛题全部材料：需求说明、规则、配置表、界面说明、原型、评分表、用例模板。摘出原文名词，后文只用这些词。
2. 判断类型。游戏，尤其是策略 / 养成 / 远征，走「游戏需求五层」和后文的模块提问。其他类型仍用同一套输出格式、用例字段和方法；把「玩家主循环」换成业务主流程，维度改成功能、数据、接口、权限、异常、兼容。
3. 划定范围。时间不够时，主循环、资源守恒、战斗结算、付费到账、存档恢复写到用例级；其余模块至少有测试点，并在未覆盖说明里写残留风险。
4. 先写测试需求，再写测试点，再选方法，最后落用例。一条用例只钉住一个判定点。
5. 重点用例必须标出设计方法。方法用来覆盖规则，方法名本身不产生分数。
6. 输出前按自检清单过一遍。缺项补上，或写入「未覆盖说明」。

## 游戏类需求怎么分析

《城邦远征》这类题目的典型对象：城建、资源经济、兵种与战斗数值、远征关卡、任务 / 成就、背包与道具、商城付费、活动、社交 / 联盟、新手引导、存档与网络同步、兼容性与性能。分析时按下面五步把原文收成可测试需求。

### 1. 名词与玩家主循环

写清玩家是谁、一轮操作要完成什么、成功和失败在界面上各是什么。

《城邦远征》的主循环写法：进入城邦 → 收取资源 → 建造或升级 → 训练兵种 → 编队远征 → 战斗结算 → 领奖并回流城建。引导、任务、商城、活动、联盟都挂在这环上，单独说明它们在哪一步插入。

### 2. 五层归类

每条需求归进一层，跨层的拆开写：

1. **玩家目标**：建好某建筑、打过某关、完成某任务、加入联盟。
2. **规则**：解锁、消耗、产出、公式、胜负、掉落、冷却、次数与上限。
3. **状态**：建筑、队列、部队、关卡、订单、活动、邮件的生命周期。
4. **系统交互**：资源、道具、货币在模块之间的进出；哪一侧是权威数据（客户端展示 / 服务器结算）。
5. **质量属性**：弱网、重入、多端、时间、性能、兼容、引导是否会卡死、结算是否可被重复触发。

测试需求格式：

- 编号：`TR-模块-序号`
- 陈述：在【条件】下，【动作】之后，【可观察结果】
- 判定依据：界面、数值、存档或协议返回；两边都有时写明以哪一个为准
- 风险：阻断主循环 / 资源或付费错误 / 仅体验
- 假设：原文没写死、作答时暂时采用的解释
- 待澄清：不把猜测写进陈述

### 3. 资源闭环

对每种核心资源（以赛题为准，常见为粮食、金币、人口、体力、加速道具、付费货币）列出：来源、去向、存放处、上限、不足时的表现、失败是否回滚、离线是否继续变化。

后续任何操作都要能回答：成功时「减少量 = 增加量 + 手续费或损耗」；失败时双方数量都不变。上限截断要单独写。

### 4. 时间线

把建造耗时、训练耗时、行军、冷却、活动开始与结束、跨天重置、离线收益上限、加速道具收成时间点。这些点全部进入边界值，不散落在功能描述里。

### 5. 权威数据

分开写展示文案、客户端预计算、服务器结算。预期以赛题指定的权威为准。预览和结算都存在时，增加测试点：预览值与结算值不一致时，以结算写回，并有可观察提示或战报。

### 模块提问

读到对应模块就回答这些问题；赛题没写的进待澄清，不补设定。

| 模块 | 从原文里抽出的问题 |
| --- | --- |
| 城建 | 队列上限、建造 / 升级 / 拆除 / 加速 / 立即完成、前置建筑、占地、升级中能否使用、取消返还比例 |
| 资源经济 | 产出建筑、仓储上限、被掠夺或税收、离线产出、资源转换、不足时队列是否暂停 |
| 兵种与战斗 | 训练与晋级、克制、战力、伤兵与阵亡、战报字段、随机、撤退损失、取整顺序 |
| 远征关卡 | 解锁、体力或次数、扫荡、星级、首通与重复奖励、失败是否消耗、中途撤退 |
| 任务 / 成就 | 计数时机（接取前的行为算不算）、跨天、进度是否丢失、奖励领取与补领 |
| 背包与道具 | 堆叠上限、绑定、使用条件、过期、回收、满包时奖励去向 |
| 商城付费 | 价格、限购、折扣叠加、支付成功 / 失败 / 结果未知、发货、重复回调 |
| 活动 | 时间窗、档位、重置、重复领取、结束后的未领奖励 |
| 社交 / 联盟 | 入盟退盟、帮助加速、职位权限、捐献、退出后建筑或资源归属 |
| 新手引导 | 强引导能否跳过、弱引导、杀进程后续到哪一步、引导与真实规则冲突时听谁的 |
| 存档与同步 | 本地与服务器冲突、顶号、战斗或建造中掉线、重进后的状态 |
| 兼容与性能 | 赛题点名的分辨率、异形屏、低内存、城内对象数量、挂机时长、加载与帧率口径 |

## 测试点拆解维度

范围内每个模块按适用维度列测试点。维度用不上就跳过，并在该模块下写一句「不适用」，不用空行凑数。

| 维度 | 要钉住的问题 | 在《城邦远征》里落在哪 |
| --- | --- | --- |
| 功能正确性 | 操作是否完成、提示是否对应原因 | 建造、出征、领奖、购买、入盟 |
| 规则与数值 | 公式、取整、克制、概率、上下限 | 伤害、耗时、产出、消耗 |
| 状态与时序 | 合法迁移、禁止迁移、中途打断 | 建造队列、远征、订单、活动 |
| 资源闭环 | 扣增成对、失败回滚、上限截断 | 粮食、兵力、货币、背包格 |
| 解锁与进度 | 等级、前置、星级、次数 | 建筑、兵种、关卡、入口 |
| 经济与付费 | 价格、限购、不到账、重复到账 | 商城、礼包、月卡 |
| 随机与奖励 | 掉落池、保底、去重、满包 | 远征、任务、活动 |
| 并发与重入 | 连点、双端、超时重试、队列争用 | 领奖、升级、出征、购买 |
| 时间 | 加速、跨天、活动窗口、离线上限 | 建造完成、每日任务 |
| 存档与同步 | 杀进程、断线、覆盖、顶号 | 城建进度、战斗中掉线 |
| 引导与易用 | 步骤能否继续、返回、卡死 | 新手引导 |
| 兼容与性能 | 分辨率、低端机、长时间、大量单位 | 城内建筑多、战报 |
| 安全边界 | 重复领奖、越权查看、篡改结算被拒绝 | 只写应观察到的拒绝和资源不变 |

编号：`TP-模块-维度-序号`，并链到 `TR`。

厚度：主循环、战斗数值、资源闭环、付费、存档写到能直接派生用例。设置、图鉴、纯文案保持测试点即可。

**重点测试点**满足任一条即可标「重点」：多个条件共同决定结果、状态会被打断、数值在阈值两侧变化、失败必须回滚、同一奖励或同一笔扣费可能发生两次。单字段的格式校验不标重点。

## 设计方法在游戏里怎么用

按规则选方法，再写用例：

- 输入或状态能分区：等价类；区间有序再加边界值
- 对象有生命周期：状态迁移
- 多个条件一起决定一个结果：判定表
- 玩家要走完多步才达到目标：场景法
- 公式、配置、产出和消耗：数值平衡验证
- 连点、双端、重试、断线：异常与并发

一条用例标一个主方法，辅方法写在备注。

### 等价类

1. 列出互相独立的维度（资源够不够、功能解锁没有、道具过期没有）。
2. 每个维度分成有效类和无效类。
3. 多个有效类可以合进一条正向用例。每个无效类单独一条，让失败原因能对上那一句提示。

出征示例（赛题若规定：粮食 ≥ 100 且兵营已解锁才可出征）：

| 类 | 数据 | 用例 |
| --- | --- | --- |
| 有效 | 粮食 ≥ 100 且兵营已解锁 | 一条正向，进入行军并扣粮 |
| 无效 | 粮食 < 100，兵营已解锁 | 单独一条，提示粮食不足，粮食不变 |
| 无效 | 粮食 ≥ 100，兵营未解锁 | 单独一条，提示未解锁，粮食不变 |
| 无效 | 粮食为 0 | 归入「粮食不足」，不另造规则 |

「粮食不足而且未解锁」若赛题没规定提示优先级，不把它写成唯一异常用例；放进待澄清，假设只作为判定表的一条。

### 边界值

在有序等价类的边界上取值。闭区间 \[min, max\] 取 min−1、min、max、max+1；步长不是 1 时按最小步长。游戏里优先覆盖：

- 等级：0、1、最大等级、最大等级 + 1
- 数量：0、1、上限 − 1、上限、上限 + 1
- 比较：比阈值少 1 个最小单位、等于阈值、多 1 个最小单位（战力、资源、概率、队列）
- 时间：开始前 1 秒、开始时刻、结束时刻、结束后 1 秒；跨天 23:59:59 与 00:00:00
- 容量：背包空、剩 1 格、已满；奖励件数 = 空格、奖励件数 = 空格 + 1
- 取整：结果为整数、刚好比整数多不足 1 的小数、刚好到达加成上下限

预期里写明取整方向。赛题没写方向时，该条进待澄清，假设单独列出，不写进「需求陈述」。

### 状态迁移

先列出状态、触发事件、守卫条件、伴随动作（改资源、改冷却、改次数）。覆盖四组：

- 每条合法迁移至少一条用例
- 每条原文禁止的迁移一条用例
- 迁移过程被打断：取消、断线、加速、超时
- 已经处于目标状态时再次触发同一事件

远征示例：

```text
空闲 --出征成功--> 行军中 --到达--> 战斗中 --结算完成--> 待领奖 --领取成功--> 已领奖
行军中 --撤退--> 空闲（按原文返还或扣除）
战斗中 --杀进程后登录--> 服务器已记录的状态
待领奖 --背包已满仍领取--> 仍为待领奖，奖励不丢
已领奖 --再次领取--> 已领奖，奖励数量不变
```

每条箭头写进测试点，重点箭头写用例。

### 判定表

条件桩用能判断真假的句子，动作桩用可观察结果（允许出发、提示原文、扣哪种资源、状态停在哪）。

步骤：列全条件 → 填规则 → 划掉需求定义为不可能的组合 → 合并不影响结果的条件 → 剩下每条规则一条用例。

出征示例。条件：C1 粮食 ≥ 100，C2 队列未满，C3 关卡已解锁。动作：A1 进入行军并扣除 100 粮食；A2 提示粮食不足；A3 提示队列已满；A4 提示关卡未解锁。任一失败都不扣粮食。

| 规则 | C1 | C2 | C3 | 动作 | 是否重点 |
| --- | --- | --- | --- | --- | --- |
| R1 | 真 | 真 | 真 | A1 | 是 |
| R2 | 假 | 真 | 真 | A2 | 是 |
| R3 | 真 | 假 | 真 | A3 | 是 |
| R4 | 真 | 真 | 假 | A4 | 是 |
| R5 | 假 | 假 | 真 | 待澄清。假设只提示 C1，不扣粮 | 是，标假设 |

两个失败条件同时出现时，提示顺序以赛题为准；赛题没写就保持 R5 这种「假设」行，不伪装成原文。

### 场景法

1. **基本流**：从入口到玩家目标完成的最短成功路径。新手引导至少一条从进游戏到第一次远征领奖的基本流。
2. **备选流**：加速、换队、使用道具、联盟帮助、中途返回再进入。
3. **异常流**：资源被另一次操作花掉、断线、支付结果未知、领奖时背包已满。

每条流写起点、步骤、成功判据、失败时资源回滚到哪。场景中的单个判定点引用判定表用例，不把整张表抄进场景步骤。

### 数值平衡验证

验证的是规则能否复核：给定输入，产出唯一可判定的预期。

1. 把公式拆开：基础值、加算、乘算、克制、暴击、上下限、取整。按原文顺序计算，顺序本身是测试点。
2. 档位至少取：最小有效值、常见中间值、上限、刚好跨过阈值的两侧。每个档位给出手算预期。
3. 资源速率：产出 × 时长 − 消耗，再施加上限。离线收益不超过配置上限；时长为 0、1 秒、上限时长、上限 + 1 个计时单位都要有结论。
4. 叠加：同类加成是否有上限；百分比和固定值谁先算。
5. 随机：原文给了概率时，写清口径（固定种子，或样本量与允许偏差）。没有种子时，单次用例的预期写「结果落在掉落池内，且权重配置和为 1」；大样本统计另列一条，并注明依赖工具。
6. 守恒：成功时来源减少量等于去向增加量（含手续费）；失败时两边都不变；达到上限时多出的部分按原文截断或丢失，并在预期里写明。

安全相关只断言可观察结果：伪造或篡改后的结算被拒绝，资源与奖励保持拒绝前的服务器数值。不写修改客户端、改内存、伪造支付回调的步骤。

伤害示例（仅演示写法，数字以赛题公式为准）：伤害 = floor((攻击 − 防御) × 克制)，最低为 1；克制取 1.0 或 1.5。

| 用例 | 输入 | 预期 |
| --- | --- | --- |
| 下限 | 攻击 10，防御 10，克制 1.0 | 伤害 1 |
| 取整临界 | 攻击 11，防御 10，克制 1.5 | floor(1.5) = 1 |
| 整数结果 | 攻击 12，防御 10，克制 1.5 | floor(3) = 3 |

### 异常与并发

每条写清触发方式和最终一致的状态，预期里给出资源前后值。

| 情形 | 游戏里的触发 | 预期里要写明的内容 |
| --- | --- | --- |
| 连点 | 建造、升级、出征、领取、购买各连点一次 | 只生效一次，或第二次有对应提示 |
| 超时重试 | 同一请求超时后原样重发 | 不双扣、不双发；状态只前进一格 |
| 双端 | 两台设备同时领同一奖励或花同一笔资源 | 只有一侧成功；另一侧提示失败；账面对得上 |
| 中断 | 请求发出后杀进程、切后台、断网再重连 | 以服务器状态为准，重进后界面追上 |
| 时间竞态 | 活动结束瞬间领取；跨天重置与领取同时发生 | 奖励按原文归属（可领或已过期），不重复入账 |
| 队列争用 | 最后 1 个建造位或出征位被两个操作同时占用 | 只占用一次；另一操作失败且不扣资源 |

「系统正常」「与需求一致」不能作为预期。

## 用例模板与优先级

### 字段

| 字段 | 要求 |
| --- | --- |
| 用例编号 | `TC-模块-序号`，全卷唯一 |
| 测试点 | `TP` 编号 |
| 关联需求 | `TR` 或原文条款号 |
| 标题 | 条件 + 操作 + 结果 |
| 是否重点 | 是 / 否，对应上文重点测试点 |
| 优先级 | P0 / P1 / P2 / P3 |
| 设计方法 | 等价类、边界值、状态迁移、判定表、场景法、数值、并发，选一个主方法 |
| 前置条件 | 账号进度、资源数量、时间、网络、队列占用 |
| 测试数据 | 具体数值，边界写明 |
| 步骤 | 一步一个动作，选手或测试人员能照做 |
| 预期结果 | 界面文案、数值变化、状态名、是否回滚 |
| 备注 | 假设、配置依赖、辅方法 |

赛题模板字段名不同时，改用赛题字段名，上表信息都要有着落。

### 优先级

- **P0**：主循环走不通；付费不到账或重复扣费；存档丢失或进度错乱；资源被多发或被吞且不能按规则恢复；篡改结算仍被接受。
- **P1**：核心规则错误（伤害、消耗、解锁、任务计数、掉落）；状态卡死；重复领奖；跨天或活动边界错误。
- **P2**：次要系统、非关键提示、引导可绕过但主流程能继续、单个兼容性组合。
- **P3**：文案、动效、低频排列。

调整规则：

- 涉及付费、资源守恒、存档、可重复领取的奖励，最低 P1；会造成损失或超发则为 P0。
- 有明确提示且不挡住主循环的纯表现，放到 P3。
- 同一规则只把代表值和临界值放在 P0/P1，其余等价类顺延，避免十条同类用例全是 P0。

条数有限制时的保留顺序：每个重点测试点的 P0/P1 用例 → 主循环基本流 → 资源回滚与并发 → 其余边界。P3 可以只留测试点。

### 去重

同一前置、同一步骤、同一预期只留一条。边界用例已经覆盖的等价类代表值不再抄一遍，追溯矩阵里注明「由 TCxx 覆盖」。

## 示例片段

下面的规则和数字只说明写法。正式答卷全部改成赛题原文，不要把示例数字带进答卷。

**测试需求**

TR-远征-01：粮食 ≥ 100、出征队列未满、目标关卡已解锁时，玩家确认出征，状态变为行军中，粮食减少 100。任一条件不满足时停留在城内，粮食不变，并提示对应原因。

**测试点**

- TP-远征-规则-01（重点）：三条件都满足时出征并扣粮。方法：判定表 R1。
- TP-远征-规则-02（重点）：粮食 99 时拒绝。方法：边界值。
- TP-远征-并发-01（重点）：双端同时出征只成功一次。方法：并发。
- TP-远征-状态-01（重点）：已领奖再次领取不增加奖励。方法：状态迁移。

**用例**

TC-远征-01 · 重点 · P0 · 判定表 R1 · TR-远征-01

- 前置：粮食 100，队列 0/1，关卡 1 已解锁
- 步骤：打开关卡 1，确认出征
- 预期：状态为行军中；粮食为 0；出现行军倒计时

TC-远征-02 · 重点 · P1 · 边界值

- 前置：粮食 99，其余同 TC-远征-01
- 步骤：确认出征
- 预期：状态仍为城内空闲；粮食仍为 99；提示粮食不足

TC-远征-03 · 重点 · P0 · 并发

- 前置：粮食 100，队列 0/1
- 步骤：两个客户端同时确认出征
- 预期：只有一支部队进入行军；粮食只减少 100；另一次提示队列已满或操作无效

**追溯（一行）**

TR-远征-01 → TP-远征-规则-01 → 判定表 → TC-远征-01 → P0 → 重点

## 写作要求

- 预期结果写出状态名、数值前后值和提示原因。
- 每个无效等价类单独成用例，失败原因与提示一一对应。
- 原文没有的公式放在假设或待澄清，不写进测试需求陈述。
- 支付和防篡改用例只描述拒绝后的界面与资源，不描述篡改做法。
- 本技能示例中的粮食 100、伤害公式等，只用于演示字段，答卷以赛题为准。
