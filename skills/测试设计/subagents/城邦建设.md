# 子任务提示词：城邦建设子系统

你只设计「城邦建设子系统」的测试用例。被测对象是接口和逻辑，没有界面。

不要输出测试规格说明书、testspec、测试计划或需求分析。不要设计军队组建、领地争夺、积分结算的流程；这些系统若提供资源或等级，只把具体数字写进前置。

## 依据

只使用调用方附上的赛题摘录。阈值、公式、错误码、建筑名称都来自摘录。摘录没有的规则不要编成用例，在表后用「待确认」各写一行。

## 设计方法

对摘录里的每个输入和每条规则选用适用的方法。一条用例一个判定点。

- **等价类 / 边界值**：等级取 0、1、上限−1、上限、上限+1。资源取 0、消耗−1、刚好等于消耗、消耗+1。产出时间取 0、1 个计时单位、达到上限的时长、再加 1 个单位。
- **非法输入**：缺少必填参数、类型错误、未知建筑、负数资源或等级。预期为摘录中的错误码；未给错误码则预期拒绝，且等级和资源都不变。
- **状态迁移**：覆盖摘录中的建筑状态。至少包括未建成到建成、升级成功、已达上限再升级、条件不足时状态不变。
- **判定表**：升级或建造由多个条件共同决定时，全部满足一条；每个条件单独不满足各一条。任一条件失败时资源不扣、等级不变。
- **数值**：产出和消耗按摘录公式计算，写明取整方向。覆盖结果为 0、刚好整数、差一个最小单位、超过持有上限。
- **不变量**：成功时资源减少量等于规则消耗，等级增量等于规则增量。失败时资源、等级、状态与调用前相同。操作后资源不为负，等级不超过上限。
- **异常**：每个错误码一条。对同一建筑并发或重复升级：只生效一次，资源只扣一次。

## 易错点

下面每条都要有用例。摘录未定义该规则时改为待确认。

- **升级条件**：前置建筑或前置等级不满足、刚好满足、高于要求。条件不满足时不得升级。
- **资源扣减**：不足、刚好、充足。成功后余额正确。失败不扣。不得把资源扣成负数。
- **等级上限**：当前等级为上限时拒绝再升级；上限−1 时可以升到上限，不能升到上限+1。
- **资源产出**：这是后续组军的输入。按公式和取整核对产量；时间为 0 时不产出；达到仓储上限后不再增加。

## 输出

只输出一张 Markdown 表，列顺序固定：

编号、子系统、标题、前置、输入、预期结果、设计方法、优先级

子系统一律填「城邦建设」。编号从 `TC-建设-01` 递增。

优先级：P0 为主规则算错或资源不守恒；P1 为边界、非法输入、错误码和条件组合；P2 为其余。

表后仅保留「待确认」列表；没有则写「待确认：无」。
