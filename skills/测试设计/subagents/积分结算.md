# 子任务提示词：积分结算系统

你只设计「积分结算系统」的测试用例。被测对象是接口和逻辑，没有界面。

不要输出测试规格说明书、testspec、测试计划或需求分析。不要重写战斗过程。胜负、平局、归属、占领领地数在前置或输入里写成已经确定的结果。

## 依据

只使用调用方附上的赛题摘录。计分公式、权重、排名规则、并列规则和错误码都来自摘录。摘录没有的规则不要编成用例，在表后用「待确认」各写一行。

## 设计方法

一条用例一个判定点。

- **等价类 / 边界值**：单项得分取 0、1、刚好达到上榜或档位阈值、阈值−1、阈值+1。领地数、胜场数取 0 和 1。总分取公式允许的最小、最大。
- **非法输入**：缺少战斗结果、未知势力、负数胜场或负数领地、结果枚举之外的值。预期为错误码或拒绝，积分和排名都不变。
- **状态迁移**：未结算到已结算。已结算再次结算时状态保持已结算。无战绩的势力保持初始分。
- **判定表**：若名次由积分、胜场、占领数、用时等多个键决定，覆盖摘录中的排序键组合。同分时按并列规则各一条：并列名次、下一名是跳号还是连续，以摘录为准。
- **数值**：按公式逐步手算，写进取预期结果，并写明先乘后加还是先加后乘，以及取整方向。覆盖进位边界、全 0、单项极大导致溢出或超过分数上限。
- **不变量**：一次有效结算后，积分增量等于公式结果。拒绝的结算不改变任何势力的积分和排名。所有势力积分之和的变化量等于摘录允许的新增积分。
- **异常**：每个错误码一条。同一战斗标识重复结算：积分只增加一次，排名只更新一次。并发提交同一结算：最终增量只计入一次。

## 易错点

下面每条都要有用例。摘录未定义该规则时改为待确认。

- **计分公式**：每一项单独为 0，其余项正常，用来核对这项的系数。全项都有值时核对合并与取整。胜、负、平对积分的影响分开写。
- **排名并列**：两方积分相同；三方相同；同分但次级排序键不同。写明名次数字。
- **边界**：0 分、刚好上榜、差 1 分未上榜、分数上限、上限+1 的处理。
- **重复结算**：同一结果提交两次；并发提交两次。第二次不改变积分和排名。

## 输出

只输出一张 Markdown 表，列顺序固定：

编号、子系统、标题、前置、输入、预期结果、设计方法、优先级

子系统一律填「积分结算」。编号从 `TC-积分-01` 递增。

优先级：P0 为公式算错、排名错、重复结算仍加分；P1 为边界、并列、非法输入、错误码；P2 为其余。

表后仅保留「待确认」列表；没有则写「待确认：无」。
