# 子任务提示词：军队组建系统

你只设计「军队组建系统」的测试用例。被测对象是接口和逻辑，没有界面。

不要输出测试规格说明书、testspec、测试计划或需求分析。不要展开城邦建设、领地争夺和积分结算。资源、人口、兵种上限若来自其他系统，在前置里写成具体数字。

## 依据

只使用调用方附上的赛题摘录。兵种名称、配比、人口或编制上限、消耗和错误码都来自摘录。摘录没有的规则不要编成用例，在表后用「待确认」各写一行。

## 设计方法

一条用例一个判定点。

- **等价类 / 边界值**：每种兵的数量取 0、1、配比要求值、编制上限、上限+1。人口取允许值−1、允许值、允许值+1。资源取消耗−1、等于消耗、消耗+1。
- **非法输入**：未知兵种、负数数量、空编制、数量为小数或非数字、缺少兵种字段。预期为错误码或拒绝，且资源、人口占用、军队数量都不变。
- **状态迁移**：覆盖摘录中的军队状态，例如未组建、已组建、已解散。重复组建、解散后再组建、对已出征或已锁定的军队再次组建时，按摘录接受或拒绝。
- **判定表**：兵种配比、人口上限、资源是否足够共同决定能否组建。全部满足一条；每一项单独不满足各一条。失败时资源不扣、人口不占用。
- **数值**：消耗、人口占用、各兵种数量按摘录计算。配比用整数比时，写明余数如何处理。合计刚好等于上限、超过上限各一条。
- **不变量**：成功时资源减少量等于消耗，各兵种数量之和等于编制，人口占用增加量等于规则。失败时这些量都不变。兵种数量和人口不为负，编制不超过上限。
- **异常**：每个错误码一条。并发两次组建同一支军队：只成功一次，资源只扣一次。

## 易错点

下面每条都要有用例。摘录未定义该规则时改为待确认。

- **兵种配比**：符合要求的比例、某一兵种少 1、某一兵种多 1、只有单一兵种、兵种齐全但比例颠倒。
- **人口 / 编制上限**：总人数等于上限可以组建；上限+1 拒绝。人口剩余刚好够、少 1 各一条。
- **资源不足**：持有量比消耗少 1 时拒绝，余额不变，不产生军队。刚好等于消耗时成功并且余额为 0 或为规则规定的剩余值。
- **部分成功**：多种资源或多种兵只满足一部分时，不允许只扣掉已满足的那一部分。

## 输出

只输出一张 Markdown 表，列顺序固定：

编号、子系统、标题、前置、输入、预期结果、设计方法、优先级

子系统一律填「军队组建」。编号从 `TC-组军-01` 递增。

优先级：P0 为主规则算错、资源或人口不守恒；P1 为边界、非法输入、错误码、配比组合；P2 为其余。

表后仅保留「待确认」列表；没有则写「待确认：无」。
